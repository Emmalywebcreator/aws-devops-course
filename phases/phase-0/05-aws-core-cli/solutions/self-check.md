# Answers · 0.5 self-check

> Not linked from the module. Answer first.

1. A key is a long-lived password stored in a file: it never expires on its own, and it gets copied into chats, screenshots and Git. A role gives **temporary** credentials that expire and rotate automatically and exist only on the machine the role is attached to, so there is nothing to leak and nothing to forget to delete. It also means no secret ever has to be put on the instance (Lab 4: `~/.aws` didn't even exist).
2. **Security group:** attached to an instance's network interface; **stateful** (replies to allowed traffic are allowed automatically); **allow rules only** (nothing allowed inbound by default). **Network ACL:** attached to a *subnet*; **stateless** (each direction is checked on its own, so return traffic needs its own rule); **has both allow and deny rules**, evaluated in rule-number order (the default ACL allows everything).
3. **`DeleteBucket` is refused** and **`ListBucket` is allowed.** The rule: a request is denied by default; an Allow lets it through; but **any explicit Deny overrides every Allow**. `DeleteBucket` matches the explicit deny; `ListBucket` matches only the allow.
4. A **route in the subnet's route table sending `0.0.0.0/0` to an internet gateway**. Show it with `aws ec2 describe-route-tables --filters Name=association.subnet-id,Values=<subnet> --query 'RouteTables[].Routes[]'`. A subnet's name doesn't matter.
5. It bills **by the hour from the moment it exists** (about USD 0.045/h ≈ USD 1.10/day, plus its Elastic IP) whether or not any traffic uses it, and it's easy to forget because nothing visibly "runs". Two commands prove none is left: `aws ec2 describe-nat-gateways --filter Name=state,Values=pending,available --query 'NatGateways[].NatGatewayId' --output text` (no output) and `aws ec2 describe-addresses --query 'Addresses[].PublicIp' --output text` (no output).
6. The NAT gateway itself needs a route **to** the internet, which only a public subnet has (`0.0.0.0/0 → igw`), because it must reach the internet on behalf of the private instances. The **private** subnet's route table sends `0.0.0.0/0` **to the NAT gateway** (`nat-…`) and has no route to an internet gateway, so nothing from outside can start a connection into it.
7. The security group only allows your `/32`, and a security group **silently drops** packets from anyone else; it doesn't answer. A dropped packet gives no reply, so the client waits and times out. "Connection refused" would mean a machine **answered** that nothing was listening (0.2).
8. IMDSv2 requires a **session token**, obtained first with a `PUT` request, before the metadata service will answer (so a bug that only lets an attacker make simple `GET` requests can't read the instance's role credentials). With IMDSv2 required, a plain request without a token gets `401`; with it turned off (IMDSv1 allowed) that same plain request would have returned the metadata listing with status `200`.
