# Answers · 0.4 self-check

> Not linked from the module. Answer first.

1. Logging gives each line a **timestamp** and a **severity level** (so you can find the one `ERROR` among thousands of `INFO` lines, and turn `DEBUG` detail on only when needed). It can also write to a **file and the screen at the same time**, and you can change what is shown without editing the code that produces the messages. `print` has none of that.
2. A key in a script ends up in Git history, screenshots and backups, and then it's leaked (0.3). The Lab 6 script created a client with no key in it; `boto3` found the credentials itself, in its fixed order. The log line `Found credentials in shared credentials file: ~/.aws/credentials` said which one it used (the `p0-readonly` profile).
3. `subprocess` is the wrong choice when a Python library already does the job (`requests` instead of `curl`, `boto3` instead of the `aws` CLI): you'd be parsing text instead of getting structured data and real exceptions. It is also dangerous with `shell=True` plus any input from outside. `check=True` makes `subprocess.run` raise `CalledProcessError` when the command exits non-zero; without it, a failed command is silently ignored and your script carries on as if it had worked.
4. (a) `requests.exceptions.ReadTimeout`. (b) `lab2_check.py`, line 20, in `main`: `response = requests.get(url, timeout=args.timeout)`. Read from the bottom up: the last line is the error, and the last frame that is *your* file (not `site-packages`) is where it came from. (c) The server didn't answer within 3 seconds: is it up and reachable (`curl -m 3 <url>`), is it slow, is the timeout too small?
5. A venv gives each project its own packages, so projects can't break each other and nothing is installed into the system Python. A **pinned** `requirements.txt` makes every install get the exact same versions, so "it works on my machine" and "it works on yours" mean the same thing.
6. (1) **Relative paths**, which depend on the current folder: build paths from `__file__` or use absolute paths. (2) **Missing environment** (variables, `PATH`, tools): check required variables explicitly and fail with a clear message, and set what the job needs in the scheduler's configuration, not in your own shell.
7. `git filter-repo` refuses to run anywhere else because the rewrite is destructive and can't be undone, and a fresh clone guarantees there's no other copy of unpublished work in that folder. The old clone still contained the secret because a rewrite only changes the repository you ran it in (and what you force-push); every existing copy keeps its old history until it's re-cloned. That's also why revoking the key comes first.
